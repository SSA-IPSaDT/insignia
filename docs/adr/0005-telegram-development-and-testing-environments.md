# [ADR-0005] Стратегия окружений разработки и тестирования Telegram-бота и Mini App

- **Статус**: Принято
- **Дата**: 2026-11-06
- **Авторы**: @naylour
- **Область (Scope)**: apps/bot | apps/app | infrastructure | tooling

---

## Контекст и проблематика

Разработка и отладка Telegram-ботов и встраиваемых Telegram Mini Apps (TMA) на платформе Insignia накладывает специфические сетевые и инфраструктурные требования:

1. **Требование HTTPS**: В стандартной (боевой) среде Telegram запрещает подключение к Mini App по незащищенному протоколу HTTP (`http://localhost:51001`), требуя действительный SSL/TLS сертификат.
2. **Вебхуки vs Long Polling**: В продакшене бот работает через вебхуки на базе высокопроизводительного HTTP-сервера Elysia (`apps/bot`). Для локальной отладки вебхуков требуется либо публичный белый URL, либо локальный сервер Bot API, либо режим Long Polling.
3. **Изоляция и стабильность**: Необходимо определить единый подход к локальному запуску и сквозному тестированию связки бот $\leftrightarrow$ Mini App $\leftrightarrow$ API, минимизируя зависимость от внешних платных сервисов и нестабильных сетевых шлюзов.

---

## Факторы принятия решения (Decision Drivers)

- **Удобство и скорость DX (Developer Experience)**: Минимальный порог входа для локального запуска `bun run dev:bot` и `bun run dev:app`.
- **Возможность работы без TLS**: Запуск Mini App напрямую с `http://localhost` без обязательной возни с самоподписанными сертификатами.
- **Поддержка локальных вебхуков**: Возможность эмулировать вебхуки без обязательного проброса портов во внешнюю сеть.
- **Стабильность внешних шлюзов Telegram**: Независимость от регулярных сбоев и вайпов тестовых серверов Telegram.

---

## Рассмотренные варианты

### Вариант 1: Использование Telegram Test Environment (Test DC)

- **Описание**: Подключение бота к официальным тестовым дата-центрам Telegram через параметр `client: { environment: 'test' }` в grammY (транслируется в `https://api.telegram.org/bot<token>/test/<method>`) и запуск Telegram Desktop в режиме `Test Server`.
- **Плюсы**:
    - **Официальная поддержка HTTP**: Telegram Test Server разрешает открывать Mini App по открытым ссылкам `http://localhost:51001` без TLS.
    - Доступ к расширенным функциям (Attachment Menu без рекламы Telegram).
    - Полная изоляция от боевых пользователей и чатов.
- **Минусы**:
    - Требуется отдельный аккаунт на тестовом сервере (через префикс `999662xxxx`).
    - **Высокая нестабильность**: Тестовые дата-центры Telegram регулярно подвергаются вайпам БД, перебоям в авторизации (ошибки `401 Unauthorized` на этапе инициализации свежесозданных ботов) и временным отключениям.
    - Невозможность использования реальных рабочих аккаунтов команды без переключения профиля Telegram.

### Вариант 2: Использование HTTPS-туннелирования (Cloudflare Tunnel / ngrok) в боевом Telegram

- **Описание**: Использование отдельного дев-бота в боевом Telegram (`@insignia_dev_bot`) в режиме Long Polling, а для Mini App — поднятие бесплатного временного HTTPS-туннеля (например, `cloudflared tunnel --url http://localhost:51001`).
- **Плюсы**:
    - 100% стабильность инфраструктуры Telegram (Production DC).
    - Работает напрямую из личного аккаунта разработчика без переключения клиентов.
    - Полная идентичность поведению в продакшене.
- **Минусы**:
    - Требуется запуск вспомогательной фоновой утилиты туннелирования (`cloudflared`).
    - При каждом перезапуске временного туннеля генерируется новый URL, требующий обновления ссылки Mini App в BotFather.

### Вариант 3: Запуск локального сервера Telegram Bot API (Docker Compose)

- **Описание**: Развертывание официального контейнера `tdlib/telegram-bot-api` в локальном `docker-compose.yml`.
- **Плюсы**:
    - Возможность полноценно отправлять и отлаживать вебхуки локально напрямую по внутренней сети (`http://host.docker.internal:51004/webhooks/telegram`).
    - Снятие ограничений по размеру файлов и тайм-аутам Bot API.
- **Минусы**:
    - Не решает проблему с открытием Mini App в клиенте Telegram (клиент все равно обращается за веб-страницей к внешнему URL или требует Test DC / туннель).
    - Дополнительное потребление памяти и зависимость от запущенного Docker-демона.

## Принятое решение

1. **Сохранение и поддержка Telegram Test Environment в архитектуре**:
    - В конфигурацию переменных окружения (`infra/env`) и сервис бота (`apps/bot`) заложена полнофункциональная поддержка `TELEGRAM_TEST_ENVIRONMENT`.
    - В планах команды — использовать тестовую среду Telegram как целевой механизм разработки для сценариев, требующих прямого HTTP-доступа к локальным ресурсам Mini App без сторонних туннелей.
2. **Фиксация текущего статуса тестового окружения**:
    - На этапе начального развертывания каркаса бота подключение к публичному Test DC Telegram столкнулось с внешней нестабильностью кластера авторизации Bot API (`401 Unauthorized` на этапе `api.getMe()` / `auth.checkBotAuthorization`).
    - Архитектурный код снабжен превентивной диагностикой: при сбое авторизации сервис выводит четкое предупреждение о несовпадении или недоступности окружения и корректно прерывает работу.
3. **Гибридная стратегия в повседневной разработке**:
    - Для повседневной продуктовой разработки сценариев бота используется режим Long Polling (`BOT_WEBHOOK_ENABLED=false`).
    - Для сквозного тестирования Mini App разработчикам предоставляется выбор: использование `TELEGRAM_TEST_ENVIRONMENT=true` (при доступности Test DC) либо туннелирование веб-хоста через `cloudflared` в обычном Telegram.

## Последствия и компромиссы

### Положительные последствия:

- Сервис бота не привязан жестко к одной среде: переключение между боевым кластером и тестовым сервером Telegram осуществляется изменением одного флага `TELEGRAM_TEST_ENVIRONMENT` в `fnox`.
- Сохранен фундамент для прозрачной локальной отладки Mini App без обязательной покупки доменов или настройки платных сервисов.
- Код адаптера Telegram чист и изолирован от деталей транспорта (`#telegram/*`).

### Ограничения и риски:

- Зависимость от аптайма тестовых серверов Telegram: при деградации Test DC разработка временно переключается на Long Polling в боевом Telegram.
