## Шаг 1: Базовые требования

Перед началом убедитесь, что в вашей операционной системе (Linux, macOS или Windows с WSL2) установлены:

- **Git** (версия 2.30+): `git --version`
- **Docker** и **Docker Compose**: `docker compose version`
- **Mise-en-place (`mise`)**: основной инструмент управления тулчейном.

### Установка Mise:

Если `mise` еще не установлен, выполните официальную команду установки:

```bash
# Для Linux / macOS:
curl https://mise.run | sh

# Проверьте интеграцию с вашей оболочкой (bash/zsh/fish):
echo 'eval "$(~/.local/bin/mise activate bash)"' >> ~/.bashrc
source ~/.bashrc

# Проверка:
mise --version
```

_(Подробнее см. на [официальном сайте Mise](https://mise.jdx.dev/getting-started.html))._

## Шаг 2: Настройка тулчейна через Mise

Клонируйте репозиторий и перейдите в его корень:

```bash
git clone <URL_РЕПОЗИТОРИЯ> insignia
cd insignia
```

В корне репозитория находится конфигурационный файл `mise.toml`. В нем зафиксированы необходимые версии инструментов:

- `bun` (1.4.4)
- `node` (26.12.0)
- `moon` (2.6.4)
- `age` (1.3.2)
- `fnox` (1.39.0)
- `hk` (2.9.0)

Выполните команду установки:

```bash
mise install
```

`mise` автоматически загрузит и активирует точные версии всех бинарников, гарантируя идентичность окружения со всей остальной командой.

## Шаг 3: Генерация Age-ключа и настройка секретов

Проект использует систему безопасного хранения зашифрованных секретов прямо в Git-репозитории с помощью **Fnox** и асимметричной криптографии **Age**.

### 1. Генерация вашего персонального ключа

Запустите встроенную задачу Mise:

```bash
mise run create-key
```

Что делает эта команда (`scripts/create-key.ts`):

1. Проверяет наличие директории `~/.config/age/`.
2. Создает приватный ключ `~/.config/age/key.txt` (если он еще не существовал) и выставляет безопасные права доступа (`0600`).
3. Генерирует и выводит в терминал ваш **публичный ключ**, начинающийся с префикса `age1...`.

### 2. Запрос доступа к секретам проекта

Скопируйте полученный публичный ключ `age1...` и отправьте его тимлиду или администратору репозитория.

Администратор добавит ваш публичный ключ в список получателей (`recipients`) в файле `fnox.toml`:

```toml
[providers.default]
type = "age"
recipients = [
    "age1qh2xqt9394fk0rqph5ax5fh64rffs6hd2ylqyqjn7kt9qr3fksqqy2ndx9",
    "age1your_new_public_key_here..."
]
```

После того как обновленный `fnox.toml` будет закоммичен в ветку, вы сможете беспрепятственно расшифровывать проектные секреты.

## Шаг 4: Установка зависимостей проекта

В качестве пакетного менеджера используется **Bun**:

```bash
bun install
```

Bun мгновенно скачает зависимости и свяжет внутренние воркспейсы (`apps/*` и `packages/*`) символическими ссылками в `node_modules`.

## Шаг 5: Запуск локальной инфраструктуры

Для локальной работы базы данных и вспомогательных сервисов используется Docker Compose:

```bash
docker compose -f infra/docker/docker.compose.yml up -d
```

Проверить статус контейнеров:

```bash
docker compose -f infra/docker/docker.compose.yml ps
```

## Шаг 6: Настройка редактора кода (IDE)

### Visual Studio Code / Cursor

Рекомендуется установить следующие плагины для максимального комфорта разработки:

- **Biome** или **Bun for VS Code** — интеграция с рантаймом Bun.
- **Tailwind CSS IntelliSense** — автодополнение CSS-классов в веб-приложении.
- **Prisma** — подсветка синтаксиса и форматирование схем базы данных.
- **Mise** — интеграция переменных и путей окружения `mise` внутри терминала VS Code.

### JetBrains WebStorm / IntelliJ IDEA

- Убедитесь, что в `Settings -> Languages & Frameworks -> Node.js and NPM` или `Bun` выбран бинарник Bun из окружения `mise` (обычно `~/.local/share/mise/installs/bun/...`).
- Включите поддержку TypeScript Language Service.

## 🔧 Устранение неполадок (Troubleshooting)

### 1. `Command not found: bun` или `moon`

- **Причина**: Оболочка терминала не активировала shims от `mise`.
- **Решение**: Выполните `eval "$(mise activate bash)"` (или для вашей оболочки `zsh`/`fish`) и добавьте эту строку в профиль вашей оболочки (`~/.bashrc` или `~/.zshrc`).

### 2. Ошибка расшифровки секретов Fnox: `failed to decrypt secret`

- **Причина**: Приватный ключ отсутствует по пути `~/.config/age/key.txt` или ваш публичный ключ еще не добавлен в `fnox.toml`.
- **Решение**:
    1. Проверьте путь: переменная `FNOX_AGE_KEY_FILE` задается в `mise.toml`.
    2. Запустите `mise run create-key` и сверьте публичный ключ с тем, что добавлен в `fnox.toml`.
    3. Убедитесь, что права на файл ключа ограничены (`chmod 600 ~/.config/age/key.txt`).

### 3. Конфликт версий портов Docker

- **Причина**: Порт локальной базы данных уже занят другим сервисом на хост-машине.
- **Решение**: Проверьте занятые порты командой `lsof -i :<порт>` или остановите конфликтующий процесс.
