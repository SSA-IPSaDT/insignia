# @insignia/logger

Единый разделяемый пакет структурированного логирования для платформы **Insignia**.

---

## 🎯 Назначение

- Единообразное логирование для всех сервисов (`apps/api`, `apps/bot`, `apps/web`) и пакетов (`packages/database`).
- Поддержка изолированных **пространств имён (namespaces)**: `api`, `bot`, `database`, `web`, а также дочерних контекстов (`api:auth`, `bot:orders`).
- **В режиме разработки**: Цветной вывод в терминал с понятными бейджами, временными метками и читаемым форматированием JSON и ошибок.
- **В файловом выводе**: Запись структурированных логов в файлы `logs/<namespace>.log` и критических ошибок в `logs/<namespace>.error.log`.
- Минимальный оверхед, работа поверх нативного рантайма Bun и Node.js без тяжёлых сторонних зависимостей.

---

## 🚀 Использование

```typescript
import { createLogger } from '@insignia/logger';

// Создание логгера для модуля API:
const logger = createLogger('api');

logger.info('Сервер запущен', { port: 3000, host: '127.0.0.1' });
logger.debug('Входящий запрос', { path: '/users', method: 'GET' });
logger.warn('Подозрительная активность');
logger.error('Сбой подключения к БД', new Error('Connection timeout'));

// Создание дочернего логгера для контекста:
const authLogger = logger.child('auth');
authLogger.info('Успешный вход пользователя', { userId: '123' });
// Выведет неймспейс: [api:auth]
```

---

## 📁 Структура создаваемых лог-файлов

При работе приложения логи автоматически группируются в директории `logs/`:

- `logs/api.log` — полный журнал событий сервиса API.
- `logs/api.error.log` — только ошибки (уровень ERROR) для быстрого мониторинга.
- `logs/bot.log` — журнал Telegram-бота.
- `logs/database.log` — запросы и события уровня БД.
